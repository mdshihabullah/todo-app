# Domain docs

**Layout: single-context**

One `CONTEXT.md` at the repo root, plus `docs/adr/` for architecture decision records.

**Consumer rules:**
- `CONTEXT.md` contains the current state of the system, technology choices, and open questions.
- ADRs in `docs/adr/` capture design decisions and their context.
- New decisions should follow the ADR template and be added to `docs/adr/`.
- Reference ADRs from `CONTEXT.md` when context is relevant to ongoing work.
